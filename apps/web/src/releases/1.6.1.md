# Sakuya 1.6.1

### Breaking
- **Sakuya now needs Bun 1.4.2 or newer.** Bun 1.3 on Windows has two bugs that took Sakuya down, both fixed below. On an older Bun, the server and the web dev server now refuse to start and tell you to run `bun upgrade`. `update.bat` / `update.sh` upgrade Bun for you, and `setup.bat` / `setup.sh` upgrade an old Bun they find.

### Fixed
- **Scans no longer crash the server on Windows.** Under Bun 1.3, generating thumbnails crashed the whole process after anywhere from a few dozen to a few hundred images, with no error in the log, usually partway through scanning a large library.
- **Playing video no longer eats all your RAM on Windows.** When the web dev server ran under Bun (the default on a machine without Node), its `/api` proxy buffered video without limit while the viewer seeked: many gigabytes within seconds, enough to freeze the PC. `limits.memory` only covers the API server, so it didn't stop this either.
- **A server that's down no longer asks for a password.** When the web UI couldn't reach the server it fell back to the login screen, even with login turned off, so a crash looked like a password you never set. The login screen now only appears when the server says login is on.
- **The Windows memory limit is reported correctly.** The boot log said `limits.memory` was "NOT enforced" on Windows even though it was being enforced.
- `setup.bat` no longer makes you restart the terminal and run it again after installing Bun, and it now notices when the Bun install fails.
