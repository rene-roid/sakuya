# Setup Guide

## Prerequisites

- [Bun](https://bun.sh) — package manager and runtime for both install and dev.

## Getting started

```bash
bun install     # installs deps for all workspaces (apps/*, packages/*)
bun dev         # starts server (:3777) and web (:5173) together
```

Or use the bundled scripts, which install Bun for you if it's missing:

```bash
./setup.sh   # or setup.bat on Windows
./run.sh     # or run.bat
./update.sh  # git pull + reinstall deps
```

Open `http://localhost:5173`. The Vite dev server proxies `/api` to the backend.

Useful variants: `bun dev:server`, `bun dev:web`, `bun typecheck`, `bun build`.

## Workspace layout

```
apps/server/   Bun + Express backend (routes/, services/, db/)
apps/web/      React + Vite frontend (routes/, components/, hooks/, lib/)
packages/shared/  Types/utils shared between server and web
docker/        nginx config for the container build
```

## Folders you shouldn't touch by hand

| Path | What it is | Why leave it alone |
|---|---|---|
| `apps/server/data/` | Runtime data dir: SQLite DB (`tbge.db*`), `thumbnails/`, `transcodes/`, `uploads/`, `models/` (ONNX tagger), `downloader/` (gallery-dl bin + cookies) | Live user data and a live SQLite file (plus `-wal`/`-shm` sidecars). Editing/deleting while the server runs can corrupt the DB or drop real libraries. Gitignored — don't try to commit it. Override the location with `SAKUYA_DATA_DIR`, don't move it manually. |
| `node_modules/` (root and per-workspace) | Installed deps | Managed by `bun install`. Never hand-edit; delete and reinstall if something's wrong. |
| `apps/web/dist/` | Vite build output | Regenerated by `bun build`. Not source. |
| `bun.lock` | Dependency lockfile | Only changes via `bun install`/`bun add`; hand-editing desyncs it from `node_modules`. |
| `.idea/`, `.junie/`, `.impeccable/` | Editor/tool-specific state (JetBrains, Junie, Impeccable hook cache) | Local tool metadata, not project source. Gitignored (except `.idea` is partially tracked — check before deleting). |
| `tray/` | Currently empty scaffold dir | Not wired to anything yet; nothing to run there. |

Anything under `apps/server/data/` is the one place that holds actual user state (your media library metadata, tags, downloaded files). Back it up before any destructive experiment; everything else here is regeneratable from source.

## Configuration

No config is required to start. Env vars, if you need them:

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `3777` | Server port |
| `SAKUYA_DATA_DIR` | `apps/server/data` | Where DB/thumbnails/uploads/models live |
| `AUTH_ENABLED` | unset | Set to `true` to require login |
| `AUTH_SECRET` | unset | Required if `AUTH_ENABLED=true` |
